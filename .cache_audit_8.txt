<!--$s2--><!--[--><!--[-1--><!--]--><!--]--><!----><!----><!----><!----><!--]--><!----><!----></div><!----></div><!--]--> <!--[-1--><!--[--><!--[--><h1>GitHub &amp; Git</h1> <p>Amp uses Git to bring your code into an <a href="/docs/orbs">orb</a> and to get the agent’s changes back out.
For repositories on GitHub, Amp signs in as you through a GitHub App connection. The agent can then
clone private repositories, push branches, open pull requests, and read CI status, and you never
have to create or paste a token. This page explains how the connection works, what Amp uses it for,
and how commits made in orbs are attributed and signed.</p> <h2 id="connect-github">Connect GitHub</h2> <p>Open <a href="/settings/integrations">Settings → Integrations</a> and click <strong>Connect GitHub</strong>.</p> <div class="docs-media-stage"><img class="docs-transparent-media" width="2306" style="aspect-ratio: 2306/1262" src="https://static.ampcode.com/docs/github-connect.png" alt="The Integrations settings page with a GitHub card that reads Allow the agent to clone and read private GitHub repositories when needed, and a Connect GitHub button"/></div> <p>GitHub walks you through two steps:</p> <ol><li><strong>Authorize Amp.</strong> This links your GitHub account to your Amp account. Amp uses the
authorization to act as you when it talks to GitHub.</li> <li><strong>Install the Amp app.</strong> Pick the account or organization that owns your repositories, then
choose <strong>All repositories</strong> or <strong>Only select repositories</strong>. Amp can reach exactly the
repositories you select here, and only if your own GitHub account can reach them too.</li></ol> <p>If you already installed the app, for example because a teammate set it up for your organization,
GitHub skips the second step. If your organization requires approval for third-party apps, an
organization owner has to approve the installation before Amp can see its repositories.</p> <p>Once connected, the card shows your GitHub login. Click the info icon to see which accounts the
app is installed on and whether it covers all or selected repositories.</p> <div class="docs-media-stage"><img class="docs-transparent-media" width="1752" style="aspect-ratio: 1752/126" src="https://static.ampcode.com/docs/github-connected.png" alt="The GitHub integration card after connecting, titled @thorsten on GitHub, with an info icon and Configure and Disconnect buttons"/></div> <ul><li><strong>Configure</strong> opens the app installation on GitHub, where you add or remove repositories.</li> <li><strong>Re-authenticate</strong> appears when the connection has expired or was revoked on GitHub. Click it to
sign in again; your repository selection stays as it is.</li> <li><strong>Disconnect</strong> deletes the token Amp holds for you. It does not uninstall the app from GitHub. To
remove the app itself, uninstall it from your <a href="https://github.com/settings/installations" rel="nofollow">GitHub application settings</a>.</li></ul> <h2 id="what-amp-uses-the-connection-for">What Amp Uses the Connection For</h2> <ul><li><strong>Creating projects.</strong> The <strong>New Project</strong> dialog lists the repositories your connection can
reach. See <a href="/docs/projects">Projects</a>.</li> <li><strong>Cloning into orbs.</strong> Before a new orb starts, Amp checks that your connection can reach the
project’s repository and then clones it into the orb.</li> <li><strong>Pushing and pull requests.</strong> <code>git push</code> and <code>gh</code> in the orb run as you. Pushes, branches, and
pull requests show up on GitHub under your account.</li> <li><strong>Commit, pull request, and CI details in threads.</strong> When the agent mentions a commit or pull
request, the thread shows a preview with its status. <a href="/docs/puck">Puck</a> uses the same
connection to check CI for you.</li> <li><strong>The Librarian.</strong> The <a href="/docs/tools#librarian">Librarian subagent</a> reads your private
repositories through your connection, in addition to all public code on GitHub.</li></ul> <p>Public GitHub repositories clone into orbs without a connection. Everything else on this list needs
one.</p> <h2 id="how-orbs-authenticate-to-github">How Orbs Authenticate to GitHub</h2> <p>Amp does not place a long-lived token in the orb. When the orb starts, Amp clones the repository
into <code>/home/user/workspace/repo</code> with a shallow, single-branch clone. The credential for that clone
applies only to the clone command and is discarded afterwards.</p> <p>After that, whenever the agent runs a Git command that talks to GitHub, Git asks a credential
helper, and the helper asks Amp for a short-lived token for your account. This means:</p> <ul><li>The agent can fetch, push, and clone any repository on github.com that your connection can
reach, not only the project’s repository.</li> <li>The <code>gh</code> CLI is preinstalled and gets its token the same way, so <code>gh pr create</code> and <code>gh run view</code> work without <code>gh auth login</code>.</li> <li>SSH URLs such as <code>git@github.com:owner/repo.git</code> are rewritten to HTTPS, so SSH keys are not
needed.</li> <li>Each Git command that contacts GitHub asks Amp for a current token. The token is never written to
disk or included in the project snapshot that later orbs start from.</li> <li>Branch protection rules and organization permissions apply exactly as if you had pushed from your
own machine.</li></ul> <p>Threads that run on a <a href="/docs/cli/runners">runner</a> or in a local CLI session use the Git
configuration and credentials of that machine. Amp does not inject credentials there.</p> <h2 id="commit-identity">Commit Identity</h2> <p>A Git identity is the name and email that appear as the author of the commits the agent makes in
orbs. Manage yours under <a href="/settings/keys#git-identities">Settings → Signing Keys → Git Identities</a>.
Your Amp account identity is available by default. To commit under another name and email, click <strong>Add Identity</strong>. Amp sends a verification link to that email, and the identity becomes usable once
you confirm it.</p> <p>Your <strong>Personal Default</strong> applies to your personal projects. To use a different identity for one
project, choose it under <strong>Git Identity</strong> on that project’s page.</p> <p>For workspace projects, workspace admins choose one policy for the whole workspace under <a href="/workspace">Workspace Settings → Projects</a>:</p> <ul><li><strong>Amp</strong> makes <code>Amp &lt;amp@ampcode.com></code> the author and adds the thread creator as a co-author
through a <code>Co-authored-by:</code> trailer.</li> <li><strong>Amp Account</strong> uses each thread creator’s Amp account identity.</li> <li><strong>User Choice</strong> lets each member pick one of their verified identities.</li></ul> <p>When you are the author, the agent adds a <code>Co-authored-by: Amp &lt;amp@ampcode.com></code> trailer to mark
the commit as made with Amp. To leave it out, set <code>AMP_DISABLE_AMP_COAUTHOR_TRAILER=1</code> as a
personal, project, or workspace <a href="/docs/orbs/handling-secrets">environment variable</a>. Commits the
agent makes through its shell also carry an <code>Amp-Thread-ID:</code> trailer with the URL of the thread, so
anyone reading the Git history can open the conversation that produced the change.</p> <h2 id="signed-commits">Signed Commits</h2> <p>Amp can sign the commits the agent makes in orbs. Amp generates an SSH keypair for you and keeps the
private key encrypted on Amp’s servers. Git in the orb calls Amp to sign each commit, so the private
key never enters the orb.</p> <p>Open <a href="/settings/keys">Settings → Signing Keys</a> and turn on <strong>Sign Git Commits in Orbs</strong>. Amp signs a
commit only when the selected Git identity uses an email you have verified, so commits made under
the <strong>Amp</strong> identity are not signed.</p> <div class="docs-media-stage"><img class="docs-transparent-media" width="1752" style="aspect-ratio: 1752/814" src="https://static.ampcode.com/docs/github-commit-signing.png" alt="The Commit Signing settings with the Sign Git Commits in Orbs switch turned on, a default Amp Commit Signing Key, and steps for verified commits on GitHub"/></div> <p>For GitHub to show the commits as <strong>Verified</strong>:</p> <ol><li>Click <strong>Copy Public Key</strong> on your default keypair.</li> <li>Open <a href="https://github.com/settings/ssh/new" rel="nofollow">github.com/settings/ssh/new</a>.</li> <li>Set <strong>Key type</strong> to <strong>Signing Key</strong>, paste the key, and save.</li></ol> <p>GitHub also requires that the committer email is a verified email on your GitHub account.</p> <h2 id="workspace-controls">Workspace Controls</h2> <p>Workspace admins can turn the GitHub integration off for the whole workspace in <a href="/workspace">Workspace Settings → Integrations</a>. The card also shows how many members have
connected their GitHub account.</p> <div class="docs-media-stage"><img class="docs-transparent-media" width="1752" style="aspect-ratio: 1752/203" src="https://static.ampcode.com/docs/github-workspace-toggle.png" alt="The workspace GitHub integration card with its switch turned on and a note that each member must connect GitHub from their personal integrations"/></div> <p>When the integration is off, members cannot connect GitHub, orbs cannot clone private GitHub
repositories, and threads do not show commit or pull request previews. Existing connections stop
working until an admin turns the integration back on.</p> <p>Each member connects GitHub from their own personal settings. There is no shared workspace token,
so every member only ever gets access to the repositories their own GitHub account can see.</p> <h2 id="other-git-hosts">Other Git Hosts</h2> <p>The GitHub connection is only for github.com. Other repositories work like this:</p> <ul><li><strong>Amp-hosted repositories.</strong> Choose <strong>Start From Scratch</strong> when you create a project and Amp
hosts the repository for you. No setup is needed.</li> <li><strong>Public repositories on other hosts.</strong> Paste the HTTPS URL when you create the project. Amp
clones it without credentials.</li> <li><strong>Private repositories on other hosts.</strong> The orb needs credentials to clone and push. See <a href="/docs/orbs/customizing#configure-git">Configure Git</a>.</li></ul> <p>GitHub Enterprise Server is not supported.</p> <h2 id="troubleshooting">Troubleshooting</h2> <table><thead><tr><th>Message or symptom</th><th>What to do</th></tr></thead><tbody><tr><td>“No GitHub account connected”</td><td><a href="/settings/integrations">Connect GitHub</a>.</td></tr><tr><td>“GitHub connection appears stale or expired”</td><td>Click <strong>Re-authenticate</strong> on the GitHub card. This happens after you revoke Amp’s authorization on GitHub.</td></tr><tr><td>“Amp could not access this GitHub repository”</td><td>Check that the URL is correct. Then click <strong>Configure</strong> and add the repository to the app installation. For organization repositories, an owner may need to approve the app first.</td></tr><tr><td>“Your GitHub account is connected, but repository access is still required”</td><td>You authorized Amp but did not install the app. Click <strong>Repositories</strong> and pick the repositories Amp may access.</td></tr><tr><td>“GitHub connection is disabled by your workspace admin”</td><td>Ask a workspace admin to turn the GitHub integration on in the workspace settings.</td></tr><tr><td>A push from the orb is rejected</td><td>The push runs as you, so the same rules apply as on your machine. Check branch protection and whether your GitHub account has write access to the repository.</td></tr><tr><td>Commits show as <strong>Unverified</strong> on GitHub</td><td>Add Amp’s public key as a
